# Skills Guide

Local routing guide for the skills installed under .agents/skills/.

Verified on 2026-08-22 against skills-lock.json and the project directory: 52 skills and 198 files. This guide is ignored by Git as a local operator aid; installed skills and skills-lock.json remain versioned.

## Selection rules

1. Start from the requested outcome, not a list of vaguely related skills.
2. Use the narrowest skill that fully owns the task. Add another only for a distinct concern.
3. Treat routers and umbrellas as coordinators; focused skills are authoritative for their subjects.
4. Do not run overlapping end-to-end workflows simultaneously.
5. Skills marked manual require explicit user selection. Other skills activate when their trigger matches.
6. Skills never override user scope, repository instructions, safety rules, or approvals.
7. Read a selected skill's complete SKILL.md and every reference it routes to before acting.

## Fast routes

| Situation | Start with |
| --- | --- |
| Unsure which engineering flow fits | ask-matt (manual) |
| Small clear implementation | implement (manual) |
| Large understood feature | to-spec -> to-tickets -> implement |
| Huge foggy effort | wayfinder (manual), then to-spec |
| Hard bug or regression | diagnosing-bugs |
| Broad native Android UI | android-design |
| Mobile UX concept or flow | mobile-app-ui-design |
| Material theme/component audit | material-design-3-ui |
| Multiple form factors | adaptive |
| Broad Android test strategy | testing-setup |
| Unclassified Compose concern | using-chrisbanes-skills |

## Overlap rules

- Android UI layers: mobile-app-ui-design (UX direction) -> material-design-3-ui (design-system semantics) -> android-design (platform implementation) -> one focused Compose skill per concern.
- Adaptive and navigation often pair: adaptive decides presentation; navigation-3 owns back stacks and scenes.
- Testing order: testing-setup -> host/device choice -> dependencies -> test structure -> assertions -> synchronization.
- Direct ADB and Gradle Managed Devices are alternative execution routes.
- Normal multi-session delivery: grill-with-docs -> to-spec -> to-tickets -> implement.
- A small settled change can start at implement; a hard bug at diagnosing-bugs; a huge foggy effort at wayfinder.
- Triage handles raw incoming reports. Tickets created by to-tickets are already agent-ready.
- Implement already includes TDD, verification, review, and commit.

## Installation caveats

- skills-lock.json records source paths and content hashes.
- using-chrisbanes-skills references uninstalled upstream targets: kotlin-api-design, kotlin-concurrency-and-flow, kotlin-control-flow, shepherd, and to-plan. Treat those routes as unavailable.
- Prefer official Android sources for API compatibility; use community skills for design/process judgment.
- Validate SDK, Compose, Material, and Navigation versions before adopting 2026 or experimental recommendations.

## Maintenance

After skill changes: compare .agents/skills/ with skills-lock.json; read changed instructions and references; update affected rows; check routers for missing targets; keep this guide ignored unless the team adopts it as shared policy.
