## Standards

1. **P1 - Saving a shortcut expense loses an underlying edit draft.** `PocketApp.kt:383` stacks a new expense over an edit, but its `onSaved` callback at `PocketApp.kt:411-414` calls `navigateRoot`, which clears the route stack at `PocketApp.kt:366-369`. The underlying draft's saved state is then removed. The added test `PocketQualityOfLifeHostTest.kt:334-366` verifies dismissing the new form, not saving it. This breaches `Info/UI-UX-Design-Philosophy.md` section 6 (preserve partially entered safe state and return to the originating surface) and section 7.1 (return to context after save).
2. **P2 - A root label is truncated at large font size.** The added one-line ellipsis on `PocketApp.kt:496` truncates "Movimientos" at 1.5x font scale on the tested phone, as recorded in `Info/verification/2026-09-28-pr34-hardware-test.md`. The corresponding rail label at `PocketApp.kt:456` uses the same constraint. `Info/UI-UX-Design-Philosophy.md` sections 6 and 8 require recognizable root destinations and large-font layouts without clipped essential actions.

No additional actionable Fowler smell or touched-component intent-security violation was established.

## Spec

1. **P2 - Unconvertible periods lack the baseline daily pace.** The PR says periods with different currencies and no usable frozen boundary rate are "shown side by side without deltas"; `Info/UI-UX-Design-Philosophy.md` section 7.2 names average daily spend as the comparison metric. With `convertedBaseline == null`, `ComparisonScreen.kt:116-132` displays only the chosen period's daily average, `ComparisonScreen.kt:140-169` omits the baseline curve and Pocket bars, and the summary table at `ComparisonScreen.kt:181-191` has no daily-average row. The user cannot compare the periods' pace even as separately labeled amounts.
2. **P2 - Saving the overlaid shortcut form drops the unsaved edit.** The behavior and evidence are the same as Standards finding 1. It also conflicts with the PR's claim that the shortcut opens a new form above an edit and with the section 6 navigation contract.
3. **P2 - Historical entry shows current-period Pocket availability.** `ProductionExpense.kt:143-145` resolves the movement's accounting period from the entered date, but the new Pocket-card values at `ProductionExpense.kt:418-437` come from `state.pockets` and use the current period's currency. `RoomPocketLedger.kt:912,944-949` defines `state.pockets` as the current period's summaries. For a historical edit or date, the card therefore labels current-period money as available without identifying the mismatch. `CONTEXT.md` defines availability within one budget period, and Issue #1 stories 21 and 32 require historical correction.

No material out-of-scope feature was established beyond the PR description and approved UI direction.

### Standards

The underlying form returns from `PocketApp` at line 435, before the only `SnackbarHost` at lines 470-472 is composed. The user sees no visual or spoken confirmation while continuing the edit, and the message can surface later after that form closes. `Info/UI-UX-Design-Philosophy.md` section 7.1 requires save success to be clear and brief; section 11 says haptics cannot be the only carrier of essential state. Provide feedback on a host visible for subordinate forms or on the restored form itself.

No additional actionable Fowler smell or touched-component intent-security violation was confirmed. The shortcut's fixed explicit forwarding and task-affinity trampoline match [Android's static-shortcut guidance](https://developer.android.com/develop/ui/compose/system/shortcuts/managing-shortcuts#start-one-activity-from-another).

### Spec

1. **P2 - The dashboard omits the previous period's daily average when the currencies cannot be converted.** `Info/UI-UX-Design-Philosophy.md` section 7.2 says that without a frozen boundary rate, both daily averages are shown in their own currencies without a difference; the PR description also promises the previous-period daily average in Inicio. `ProductionDashboard.kt:324-330` shows only a currency warning when `comparison.convertedBaseline == null`. The detailed `ComparisonScreen.kt:118-123` does show the baseline. Show that labeled value in the dashboard disclosure too.
2. **P2 - Saving a shortcut expense over an open edit gives no visible success feedback.** The implementation and evidence are the Standards finding above. `Info/UI-UX-Design-Philosophy.md` section 7.1 explicitly requires clear, brief save success; the new return-to-edit path does not meet it.
