# 1.0.6 hardware findings: fixes (2026-09-30)

## Scope

Fixes for the five non-blocking findings in the [1.0.6 hardware test record](../../Info/verification/2026-09-29-1.0.6-hardware-test.md). The branch starts from `9fb8c53`, the head of PR #38, which has since merged into `main` as `265cf74` with no further changes. The development version advances from 1.0.6/7 to 1.0.7/8. Every fix was written test-first: each new host test failed on `9fb8c53` for the reported reason and passes with the fix.

## Findings, fixes, and tests

1. **Onboarding drew under the status bar.** `OnboardingScreen` is drawn edge to edge outside the app scaffold, and its list used a fixed 24dp padding. The list's content padding is now the safe-drawing insets (system bars, display cutout, and keyboard) plus 24dp. `CenteredProgress`, the other screen outside the scaffold, now pads by the safe-drawing insets too. Other full screens (the Movement form, "Comparar periodos", Settings details) already sit in a `Scaffold` with a top app bar and were not changed.
   - Test: `PocketQualityOfLifeHostTest.onboarding_content_starts_below_the_status_bar` applies a 94px status bar, the height measured on the phone. Before the fix, the title started at 24px.
2. **Raw parser error on an invalid restore.** `BackupCodec` passed any exception message to the UI, including kotlinx's English "Unexpected JSON token at offset 0: …", which also quotes the file's first line. The codec's own checks now throw a private `InvalidBackup` and keep their specific Spanish messages. A parser failure shows "Este archivo no es un backup de Pocket o está dañado." Any other failure, such as an arithmetic overflow, shows "El backup contiene datos que Pocket no puede restaurar." A failed database write during restore now reports "No se pudo restaurar el backup. No se modificaron los datos." instead of the SQLite message; the transaction rolls back, so the claim holds.
   - Test: `PocketLedgerHostBehaviorTest.a_file_that_is_not_a_pocket_backup_is_rejected_in_spanish_without_parser_details` covers a CSV export, `{}`, and a wrong field type in both preview and restore, and checks that "Versión de backup incompatible" is kept. Before the fix, the CSV case returned the kotlinx message.
   - Extended: `restore_commit_failure_is_classified_as_persistence_and_rolls_back_replacement` now also asserts the persistence message. Before the fix it was SQLite's "forced restore failure" text.
3. **Plurals.** The restore preview and the restore result now say "1 periodo", "1 Pocket", and "1 movimiento". A shared `counted(count, singular, plural)` helper also fixes the other count strings found by a search: "1 gastos" in the Pockets period details, "de 1 días" in the spend pace, and "en 1 días" in the chart's spoken summary. "N movimiento(s)" in Movimientos and "N apps seleccionadas" already handled the singular.
   - Test: `PocketAppHostFlowTest.restore_preview_and_result_use_singular_counts` checks the preview text and the exact completion message for a one-period, one-Movement backup. Before the fix, the preview said "1 periodos … 1 movimientos".
4. **Font scale 1.5 on Inicio.**
   - "Sin asignar" and "Gastado" tiles: the dashboard now measures both amounts. When either cannot fit on one line in a half-width tile, the tiles stack at full width, so "SAR 4,200.00" stays on one line. This follows the approach PR #34 used for the comparison table. At font scale 1.0 and typical amounts, the tiles stay side by side. A non-breaking space was rejected: at this width the whole amount does not fit in a half tile, so Android would break inside the number instead.
   - Test: `PocketQualityOfLifeHostTest.dashboard_metric_amounts_stay_on_one_line_at_a_large_font_size` uses native text measurement at the S23 width (384dp). Before the fix, the amount took 2 lines.
   - "Registrar gasto" covering "Ver todos": no code change. On the S23 geometry, the extended button spans x = 143–368dp at font scale 1.5. With the tiles stacked, it still sits over the "Tus Pockets" header at rest (header y = 675–707dp, button y = 671–727dp). A floating action button is expected to overlap content at rest if every item can scroll clear of it. The whole header is also a single target that opens Pockets, so a partly covered header stays usable. The dashboard's existing 96dp bottom padding lets the last item scroll above the button. No placement of "Ver todos" is outside the button's column at every font scale, and collapsing the button would not change the vertical overlap at rest.
   - Guard: `PocketQualityOfLifeHostTest.every_dashboard_item_can_scroll_clear_of_the_extended_fab_at_a_large_font_size` scrolls the dashboard to its end at font scale 1.5 and checks that the last Pocket card ends above the button. It passes with the current padding. As a negative control, it failed when the bottom padding was temporarily cut to 16dp (card bottom 727 vs. button top 671).
5. **Capture sources are not restored.** Backup format v5 does not contain any notification capture setting. The "Registrar automáticamente" and "Aviso al detectar un gasto" switches only looked restored because both default to on. Source apps are package names from one device, and [ADR 0001](../adr/0001-plaintext-portable-backup-and-replacement-restore.md) scopes backups to the ledger and to settings that affect financial behavior. The backup format is therefore unchanged. After a successful restore, when no source app is selected, the restore result now ends with: "Si usabas la captura desde notificaciones, vuelve a elegir tus apps en Ajustes > Captura desde notificaciones; el backup no las incluye." The existing "Ninguna app seleccionada" / "Elegir apps" setup step in that screen is where the user completes the setup. The message is not shown when a source app is already selected, for example when restoring on the same install.
   - Test: `PocketAppHostFlowTest.restore_result_says_capture_needs_its_source_apps_chosen_again_when_none_are_selected` restores through onboarding, as after a reinstall. Before the fix, the result ended after the counts. The singular-count test above uses a selected source app and asserts the exact message, which checks that the note is absent in that case.

## Verification and limits

All Gradle runs went through `.agents/skills/gradle-run/scripts/gradle_run.py`.

- Before the fixes, all five new tests failed for the reasons above. After the fixes, `PocketLedgerHostBehaviorTest`, `PocketQualityOfLifeHostTest`, and the `PocketAppHostFlowTest.restore*` tests passed.
- `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest` passed. The host suite ran 282 tests with no failures, errors, or skips.
- `:app:pixel6Api35DebugAndroidTest` passed: 31 tests on the Pixel 6 API 35 managed device, none failed or skipped.
- No physical-device test was run. The onboarding inset fix is verified with an injected 94px status bar in Robolectric, not on the phone. The FAB overlap at rest is unchanged by design, as described in finding 4.
