## Spec

1. **#18 — foreground date changes may be detected late (introduced in the reviewed diff).** The issue requires a date change to be detected while the app remains visible. [`ForegroundDateCoordinator.kt`](../../app/src/main/java/com/aif31/pocket/ForegroundDateCoordinator.kt#L27) computes one wait until the old clock's next midnight, and [`MainActivity.kt`](../../app/src/main/java/com/aif31/pocket/MainActivity.kt#L90) waits for it. If the device clock advances to a later date mid-session, the displayed period may stay stale until that wait ends. Existing tests call `refresh()` directly and do not prove the scheduling path. Verify with a controlled clock change during a visible session, then cover the scheduling behavior.
2. **#20 — failing-device-test propagation is unproven (reviewed diff).** The issue requires a workflow exercise in which a deliberately failing test makes the job fail. The committed [`android-ci.yml`](../../.github/workflows/android-ci.yml#L70) runs the suite and rejects zero executed tests, but the reviewed history contains no deliberate-failure exercise. Record a failing run and retained diagnostics, then remove the intentional failure.
3. **#20 — the managed-device job is not an enforced merge gate (current GitHub configuration, outside the diff).** On 2026-09-23, GitHub's branch-protection API returned HTTP 404 for `main`; its only branch ruleset, `Basic`, reported `enforcement: disabled`. The workflow runs on `main`, but a failing job is not required before a change reaches that branch. Enable a rule requiring the managed-device check and verify it blocks a failing PR. This finding is independent of the staged GPU flag in the local workflow.
4. **#19 — share retry can use an older backup (present at the fixed point; current-`main` acceptance gap).** The issue requires retry to repeat only the failed document operation. [`MainActivity.kt`](../../app/src/main/java/com/aif31/pocket/MainActivity.kt#L151) sets `SHARE` retry for both backup preparation and share-launch failures; the retry path at [line 141](../../app/src/main/java/com/aif31/pocket/MainActivity.kt#L141) calls `shareExistingBackup`, which selects the newest cached file at [line 180](../../app/src/main/java/com/aif31/pocket/MainActivity.kt#L180). If fresh preparation fails while an older file exists, retry can share that older artifact. Distinguish preparation retry from launch retry and retain the exact artifact for the latter.
