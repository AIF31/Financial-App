## Standards

1. **Hard breach: selection semantics.** The quick-entry form's Pocket and payment-method buttons show a checkmark for the chosen item but expose no semantic selected state ([`ProductionExpense.kt:393`](../../app/src/main/java/com/aif31/pocket/ProductionExpense.kt#L393), [`:434`](../../app/src/main/java/com/aif31/pocket/ProductionExpense.kt#L434)). [`Info/UI-UX-Design-Philosophy.md:139`](../../Info/UI-UX-Design-Philosophy.md#L139) explicitly requires semantic selected state for both controls. A screen reader receives changed button text without a selection state.
2. **Hard breach: financial calculation in a composable.** [`ProductionDashboard.kt:237`](../../app/src/main/java/com/aif31/pocket/ui/ProductionDashboard.kt#L237) calculates average daily spending by dividing net spending by elapsed days in the UI. The philosophy requires dashboard values from shared domain calculations at [line 157](../../Info/UI-UX-Design-Philosophy.md#L157) and says to avoid domain calculations in composables at [line 281](../../Info/UI-UX-Design-Philosophy.md#L281).
3. **Judgement call: possible Divergent Change.** [`SettingsScreens.kt:214`](../../app/src/main/java/com/aif31/pocket/SettingsScreens.kt#L214) keeps period, reminder, payment-method, template, and data-section state in one screen function. Unrelated settings changes converge there. This Fowler smell is lower confidence and does not justify a standalone refactor without a concrete maintenance problem.

## Spec

1. **#1: offline foreign expense capture is blocked.** Stories 43–48 and the implementation decisions require an original USD/MXN amount, a manually entered SAR equivalent, and **Estimado/Confirmado** status. [`ExpenseEntryState.kt:53`](../../app/src/main/java/com/aif31/pocket/expense/ExpenseEntryState.kt#L53) rejects cross-currency entry when online FX is disabled; [`ProductionExpense.kt:288`](../../app/src/main/java/com/aif31/pocket/ProductionExpense.kt#L288) then disables Save. The form has no manual equivalent or status input. A new foreign purchase cannot be recorded with the default offline setting, and the user cannot create or later confirm a manual estimate through the form. A legacy manually converted movement can still be edited without changing its amount; that regression test does not cover new manual capture.
2. **#1: historical Pocket budgets are read-only.** Story 21 and the implementation decisions require editing historical periods and budgets so derived views recalculate. [`PocketsScreen.kt:75`](../../app/src/main/java/com/aif31/pocket/PocketsScreen.kt#L75) labels a prior period “Solo lectura”; [`PocketsScreen.kt:448`](../../app/src/main/java/com/aif31/pocket/PocketsScreen.kt#L448) shows only historical details and a Close action. Historical funds and movements have edit paths, but a mistaken prior Pocket budget cannot be corrected in the app.
