# PR #46 review and verification

Reviewed the original PR head `a1e84a943fbe92948bd8c48c3766e6899d061821`
against `main` at `f9d7ac73ac4bb1381e66b8a82a1a072b4e9f4160`.
The Standards and Spec reviews ran independently with GPT-6.1-Sol, high effort.

## Standards

1. **Unnamed rate-alert switch.** `CurrencySettings.kt` exposed a switch without
   a label, contrary to the accessibility contract in
   `Info/UI-UX-Design-Philosophy.md` section 11. Added the same content-description
   pattern as the existing notification settings switches.
2. **Budget calculations in a composable.** `SuggestedBudgetsDialog` calculated
   replacement totals and affordability, contrary to the UI philosophy's
   prohibition on domain calculations in composables. Adding each budget delta
   could also overflow before a later reduction, even when the final total fit.
   `BudgetSuggestions.plan` now sums the replacement budgets and reports their
   affordability. An unrepresentable total disables applying the plan.

No additional baseline code smell was considered actionable.

## Spec

1. **Stale merchant memory confirmation.** A newer auto-recorded expense could
   arrive after preparing a merchant reassignment. The selected older expense
   was unchanged, so the transaction succeeded without redirecting future
   automatic records. This violated the Merchant memory definition in
   `CONTEXT.md`. The transaction now checks both the selected expense's snapshot
   and that it remains the latest expense under the shared merchant resolver.
   A stale request rejects without changing either expense.

## Adversarial review

Claude Opus 5.5 at high effort confirmed the earlier fixes and found one
additional correctness issue: projecting a monthly subscription by a median
day count put an August/September/October first-of-month charge on October 31,
then November 30, rather than November 1. The regression failed with an
expected November 1 versus actual November 30 before the fix.

Consistent calendar-month histories now retain their day of month, clamped to
shorter months. The anchor survives February, including when the first observed
charge was in February. Fixed-day monthly histories and weekly schedules retain
their median interval. The expiry rule uses the correctly projected second
occurrence. Regression fixtures cover first-of-month, February and month-end
boundaries, including exclusion from the preceding budget period.

The review also noted the outdated PR version text; the live PR title and body
were corrected to `1.0.11` / code 12.

A second Opus 5.5 high-effort review confirmed the calendar fix, the earlier
fixes, pace alerts and recap behavior, with no new regressions. It noted one
residual forecasting limit: shifted monthly histories, such as August 1,
September 2 and October 1, still use the documented median-day estimate. This
was retained to avoid guessing a calendar anchor for fixed-day schedules.
Recurring charges remain estimates; this rule never records a Movement.
