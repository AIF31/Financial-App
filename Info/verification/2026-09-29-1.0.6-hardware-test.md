## Findings

1. **Onboarding draws under the status bar.** `OnboardingScreen` (`PocketApp.kt`) pads its `LazyColumn` by a fixed 24dp (about 66px here) without window insets. The status bar is 94px, so the "Pocket" title overlaps it.
2. **Raw parser error on invalid restore.** Choosing a non-backup file shows "Backup inválido" followed by the English kotlinx message "Unexpected JSON token at offset 0: …".
3. **Plurals.** The restore preview and confirmation say "1 periodos" and "1 movimientos".
4. **Font scale 1.5.** "SAR 4,200.00" in "Sin asignar" wraps between currency and number, and the extended "Registrar gasto" button covers "Ver todos" until the list scrolls.
5. **Capture sources are not restored.** A backup restores the capture toggles but not the selected source apps, so capture stays inactive after a reinstall until the user reselects them. This may be intentional because package names are device-specific; the restore flow does not mention it.

None of these block the release; no data-safety or security defect was found.

Follow-up (2026-09-30): findings 1, 2, 3, and 5 and the amount wrap in finding 4 were fixed test-first in 1.0.7. The button overlap at rest was kept as expected floating-button behavior, with a test that every item can scroll clear of the button. Capture source apps stay out of the backup; the restore result now asks the user to choose them again. See [the fixes audit](../../docs/audits/2026-09-30-1.0.6-hardware-findings-fixes.md). The fixes have not been tested on the phone.
